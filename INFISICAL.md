# Infisical deployment contract

Production deploys keep runtime configuration and secrets separate:

- `docker/.env.example.prod` documents non-secret runtime configuration.
- Infisical stores deploy credentials and runtime secrets in the `dev` or `prod` environment.
- `deploy.sh` fetches secrets on the deploy machine and delivers them to the droplet as Docker
  secret files. Secrets are never written to the repository or copied into `.env`.

## Required Infisical secrets

| Secret | Used by |
| --- | --- |
| `POSTGRES_PASSWORD` | Postgres container and internal database URL |
| `AUTH_SECRET` | System API and MCP bearer validation |
| `SESSION_SECRET` | Daily session cookies |
| `RESEND_API_KEY` | Production OTP delivery |

`EMAIL_FROM` is non-secret runtime configuration and belongs in the deploy environment
file. `DATABASE_URL` is generated by `deploy.sh` from the Postgres password unless an
explicit secret is provided by the deployment operator.

## Local setup

Install and authenticate the Infisical CLI, then export:

```bash
INFISICAL_SITE_URL=https://app.infisical.com
INFISICAL_PROJECT_ID=replace-me
INFISICAL_CLIENT_ID=replace-me
INFISICAL_CLIENT_SECRET=replace-me
```

Use `npm run bootstrap:secrets` to seed or validate the selected environment. The script never
prints secret values.
